# PRs are verified on the latest main; a workflow merges main into auto-merge PRs

The `main` ruleset requires branches to be up to date (`strict_required_status_checks_policy: true`), so two PRs that each pass cannot combine into an unverified `main`; the cost, every open PR re-running its checks when `main` moves, is accepted. Merge queues need an org-owned repo, so `.github/workflows/update-auto-merge-branches.yml` runs `gh pr update-branch` on every open, non-draft, same-repo auto-merge PR when `main` moves or a PR turns on auto-merge (via `pull_request_target`, so a PR cannot edit the job that holds the token), pushing with the `AUTO_UPDATE_TOKEN` fine-grained PAT because a `GITHUB_TOKEN` push starts no workflows and auto-merge would stall; without the secret it warns and skips, and a PR that conflicts with `main` needs a manual merge.
